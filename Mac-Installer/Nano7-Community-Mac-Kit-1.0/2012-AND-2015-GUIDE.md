# Detailed firmware + Mac guide: 2012 versus 2015

## 1. Which nano do you own?

Both use model **A1446**, 16 GB, a 2.5-inch screen, Home button, and Lightning connector. A1446 alone **does not** distinguish them.

- **2012-family:** introduced in 2012; original colours include slate, silver, green, purple, yellow, blue, pink, and red. 2013 Space Gray is generally grouped with the earlier hardware generation.
- **2015 refresh:** introduced July 2015. Gold is unambiguously a 2015-refreshed colour; late brighter blue/pink, silver, space gray and red are also offered. Silver/gray/red or blue/pink alone may not uniquely establish the hardware revision.
- Check purchasing history, detailed hardware ID / trusted serial lookup or known firmware logs when available. **Do not use colour alone for ambiguous examples.**
- In `Settings > About`, note the firmware version and serial for your own records, but **do not post serial numbers in Discord**. **Version `1.1.2` by itself does NOT prove the nano is jailbroken or that the firmware patch is the correct one.**

## 2. Choose your starting point

### A. You ALREADY have a compatible untethered homebrew firmware

Use this Mac kit. Follow `START-HERE.md`. This app pack uses a custom A/B resident startup arrangement, so compatibility depends on the startup hook your firmware actually uses. The bundle itself is the same for 2012 and 2015 devices, but the firmware needed to start it is **not interchangeable**. The files were taken from a 2015 working setup; a 2012 community hardware test is still needed.

### B. Your nano is STOCK (even if Settings says 1.1.2)

**STOP — this ZIP cannot install apps on stock firmware.** First install a supported untethered firmware using a guide for the correct 7G hardware revision and take a full 16 GB backup before doing any firmware write. There is a risk of permanent brick. Never test a firmware or restore command simply because it starts running.

The original NanoApps project recommends:

1. Read https://github.com/nfzerox/NanoApps and its firmware dependency https://github.com/nfzerox/ipod_sun_untethered .
2. Read the firmware release notes at https://github.com/nfzerox/ipod_sun_untethered/releases/tag/1.0 . There are separate source targets for `iPod_1.1.2_39A10023_2012` and `iPod_1.1.2_39A10023_2015`. **Choose the exact firmware/release asset for your revision and verify it before flashing.** Do not flash a 2015 firmware image onto an original 2012 nano, or vice versa, merely because both say `1.1.2`.
3. The project documents a **Windows iTunes restore** for its supplied firmware and a **Linux computer (including Raspberry Pi)** for the regular NanoApps app installation. **This is not a validated Mac-only first-time firmware installation procedure.** If your only computer is a Mac, wait for a thoroughly tested Mac firmware path or use another supported machine, rather than experimenting with Finder restores, random wInd3x commands or an HFS+ reformat.
4. The alternative https://github.com/olievans123/nano7-untethered documents a Linux firmware builder / staged loader workflow. Its published full hardware test was on **one silver 2012 nano**; the 2015 refresh was not hardware-tested in that release. Follow its own detailed backup and dry-run instructions, not improvised commands.
5. Once the untether is confirmed operational on the actual nano, disconnect it from the flashing/syncing machine before using this kit for the four custom apps.

**Why no Mac firmware-flashing button?** The Mac DFU/wInd3x method and the storage format (HFS+ vs FAT) introduce additional uncertainties. Working Mac recovery preparation does not mean a firmware partition write is safe. The 2012 and 2015 USB/recovery identifiers may differ; a wrong restoration can permanently brick the device. The app-file installer should not hide those risks.

## 3. If you want the FULL upstream NanoApps collection, not just these four apps

Use the original upstream project, which has its own build and install system. Plug the nano into the supported Linux machine (not directly into a Finder/iTunes sync session on your patched Mac). From your Mac, you can operate a Linux Raspberry Pi remotely through **Terminal → SSH**. Example, replacing `youruser` and `raspberrypi.local` with your actual Linux login/host:

```bash
ssh youruser@raspberrypi.local
```

**These next commands run on the LINUX machine after SSH login, not on macOS:**

```bash
git clone https://github.com/nfzerox/NanoApps.git
cd NanoApps
./start
```

Read the upstream `README.md` and select **Install all apps** in its menu. For first-time setup, the upstream script installs build dependencies and configures the connected/remote installation location. If you reboot and the app icons disappear, the official NanoApps README describes using **Install resident only** to register them again. **Do not run the full NanoApps install over the custom four-app A/B loader from this ZIP without first restoring the earlier state; their app packs/loaders conflict.**

Mac-formatted **HFS+** iPods are supported only experimentally by the upstream Linux file-writing flow. Never reformat an iPod just to make a quick step appear to work without accepting complete data loss and holding a verified image backup.

## 4. Safety checkpoints, for both revisions

Before firmware flashing: obtain full 16 GB image, verify its SHA-256, preserve any original Apple firmware, confirm model revision from a trustworthy source, review a proven recovery path, and understand that **even a full backup may not unbrick a damaged bootloader/firmware**. A charged battery and DFU accessibility are important. Do not flash on a low battery or unreliable cable.

Before Mac app file installation: confirm patched firmware already boots, mount only one nano, close Finder/iTunes device management windows, inspect the device in the kit, and keep the kit's rollback backup on the Mac.

After Mac app file installation: eject safely; test Calculator, Contacts, Chess, and Golf one at a time; restart and retest. File checksums cannot establish whether the startup hook or SCSI code execution is working.

### USB/finder notes

- On patched firmware, Finder/iTunes/Apple Devices may repeatedly reboot the nano due to the modified SCSI command channel. The upstream README suggests entering **Disk Mode** for media sync: hold Home + Sleep/Wake to start reboot; after the display goes dark and **before** the Apple logo, hold both volume buttons until Disk Mode appears. This is for normal media sync, **not a reason to flash firmware**. If you are unsure, consult the upstream README for timing.
- This kit NEVER auto-enters DFU/recovery and NEVER attempts disk erase/partition or Apple restore. It only accesses an already-mounted `/Apps` folder.
